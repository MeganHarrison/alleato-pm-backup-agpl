The guardrails that make this safe

Each exception has a visible recovery path—no silent fallback, fabricated record, or implicit approval.

Missing or ambiguous facts

Ask a targeted question or show a selection list. Never infer the vendor, commitment type, or value when the evidence is insufficient.

Evidence is stale or conflicts

Show the conflicting or dated sources and lower recommendation confidence. The user chooses or corrects the contractor before approval.

Approval, write, or recovery fails

Keep the draft and its source trail. Record the failure state; retry with the same payload key so a retry cannot create a duplicate commitment.

Approval contract: what must be bound together
  • One typed commitment draft: subcontract or purchase order, project, vendor, scope, financial fields, and validation result.
  • One immutable payload hash shown at review and used at write time.
  • One explicit approval or cancellation tied to the approving user and tool call.
  • One idempotency key and audit record with the outcome, record link, and any failure reason.
  • Source citations and recommendation rationale retained as decision support—not copied in as contractual fact.
