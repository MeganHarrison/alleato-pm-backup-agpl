### Company write boundary

- `POST /api/directory/companies` and
  `PATCH /api/directory/companies/[companyId]` fail with `403 erp_managed`.
- CRM overlay writes must remain in CRM-owned tables and must never update the
  ERP-master `companies` row.
- The existing company `DELETE` path is outside this task and is not approval
  for CRM writes to master data.

### Tasks

- Live `tasks` has no `company_id` or `crm_deal_id`.
- Durable assignment is `assignee_person_id -> people.id`; name/email fields
  are fallbacks.
- Allowed statuses are `open`, `in_progress`, `blocked`, `done`, and
  `cancelled`. CRM open-task semantics must include the first three.
- Existing task deletion is a hard delete, not the soft-delete flow assumed by
  v4. Phase 1 must define and test archive/unlink behavior before adding CRM
  provenance columns.
- Existing task create/update schemas do not accept CRM linkage fields. Direct
  writes must remain rejected until a dedicated CRM linkage boundary exists.

### Attachments

- `DocumentPickerEntityType` and `PatternCEntityType` are closed unions and do
  not include a CRM deal.
- Adding deal attachments requires extending both unions, the Pattern C
  junction mapping, and the document-picker API contract.
- `uploadEntityAttachment` requires `projectId`. A pre-conversion deal may have
  no project, so storage and authorization scope must be decided before the
  schema/API is accepted.

### Communication identity and deduplication

- `document_metadata` has 46,982 rows; only 2,338 have a `content_hash`.
- The hash is globally unique when populated, but the source identity index on
  `(source_system, source_drive_id, source_item_id)` is non-unique.
- OneDrive/SharePoint deliberately remove `content_hash` from the app catalog
  to preserve copied-file provenance. Outlook attachments reuse an existing
  content hash when available, while Outlook conversations compare a stable
  document ID plus hash.
- Cross-source canonical deduplication is therefore partial, not proven.
  Phase 1 must use the plan's `crm_source_identity` fallback unless a focused
  evaluation proves canonicalization for each admitted source.

### Scheduling and timezone

- `render.yaml` establishes Render cron as the repository's scheduled-runner
  pattern, but the file says live services are managed through the Render API.
  No Render connector or credential was available for a live readback.
- No user-level/reporting timezone setting exists. Only meeting and schedule
  calendar timezone columns are present. Reporting must use the documented
  fallback or first add an explicit preference source.

## Critical Baseline Conflict

Current main still contains an older CRM implementation even though migration
`20260724140000_drop_crm_from_pm_app.sql` removed its database objects.
Stale surfaces include CRM API routes, CRM feature components, company-detail
CRM panels, the deals client, and an AI dashboard query of `crm_deals`.

Phase 1 must begin with an explicit retire-or-replace inventory and a guardrail
that prevents any stale route from querying dropped tables. The database is
greenfield; the codebase is not.

## Authenticated Browser Preflight

Requested command:

`npm run verify:browser-auth -- --base-url https://projects.alleatogroup.com --route /directory/companies --session crm-phase0-auth`

Result: blocked before an authenticated page assertion.

- On Windows the verifier attempts to spawn `npx`, while only `npx.cmd` is
  resolvable.
- After a temporary executable shim, the production URL collided with the
  Playwright config's local `webServer` setting.
- The no-webserver equivalent then proved that Vercel `env run` did not inject
  the required Supabase/test-user variables, although their encrypted names
  exist in the project.

Recovery: make the verifier resolve Windows command shims, select the
no-webserver config for non-local origins, and fail immediately when required
provider variables are absent. Then rerun the exact command above. No secret
should be pasted into the task.
