## Failure-loudly contract

- Cause: typed authorization, project-resolution, tool/source, approval,
  persistence, runtime, or terminal-classification failure.
- Detection: durable replay ledger, paired parity report, focused tests, and
  production read-back.
- Recovery: set Eve assignment to zero, allow existing turns to terminalize,
  route new turns to legacy, repair the failed contract, and rerun the gate.

## Incident learning

- Failure fingerprint: `process.claimed-verification-without-runtime-evidence`
- Guardrail evidence: live Eve eval 24/24 and 192/192 gates, focused frontend
  and agent regressions, linked migration read-back, and final independent
  review recorded in this task.
- Root cause: the earlier atomic cutover removed the comparison runtime and tool
  breadth before real Eve parity was proven.
- Detection gap: build and mock routing evidence were treated as runtime proof.
- Prevention: legacy deletion now requires live routing, paired parity, durable
  ledger evidence, independent review, and production read-back.
- Local detection gap: the frontend could start without Eve configuration and
  silently assign local users to the legacy runtime. The canonical local
  launcher now starts the frontend and authored Eve root together, forces local
  Eve assignment, shares an ephemeral proxy secret, imports Eve's OIDC token,
  and permits HTTP only for an explicitly enabled localhost Eve origin.
- Continuation failure fingerprint:
  `eve.visible-answer-preceded-durable-terminal-by-60-seconds`.
  Root cause: the proxy persisted each Eve stream fragment separately and
  reread the full durable turn after every fragment. A 113-event response
  therefore remained `running` long after the browser displayed the answer.
  Detection gap: the browser smoke test exercised only one turn, and protocol
  tests used short streams with an in-memory repository. Prevention: stream
  events are now persisted in bounded batches, terminal events and receipts
  commit atomically, and the client stream cannot close before durable
  terminalization finishes.
- Continuation cursor fingerprint:
  `eve.continuation-used-global-cursor-as-client-cursor`.
  Root cause: the proxy exposed Eve's session-global stream offset as though it
  were the new app turn's local offset. The SDK correctly requested
  `startIndex=0`, which the proxy rejected. Detection gap: the prior two-turn
  test expected that broken rejection. Prevention: each app turn now accepts a
  local cursor and translates it to its durable Eve session offset, with a
  focused two-turn regression and the exact real-user risk question verified
  through agent-browser.
