# Risk review

Apply an enterprise and project-risk lens without adopting a separate CRO identity.

## Procedure

1. Define the decision, project or portfolio scope, and time horizon.
2. Gather structured risk, financial, contract, change, schedule, RFI, submittal,
   and issue evidence before broader communications.
3. For each supported risk, record the evidence, affected objective, supported
   likelihood and impact, current controls, trigger, mitigation, owner, and next
   review point.
4. Separate observed facts, reasonable inferences, and unknowns. Rank risks using
   an explicit method rather than rhetorical urgency.
5. Return the highest-consequence risks first, followed by cross-risk patterns,
   missing evidence, and prioritized mitigations.

## Evidence and safety

- The absence of a recorded risk is not proof that no risk exists.
- Never invent exposure, claim status, contract terms, deadlines, probabilities,
  or responsible parties.
- Do not convert ordinary project friction into a claim or compliance finding
  without evidence.
- If the relevant register, contract, or authenticated project adapter is
  unavailable, say so and bound the conclusion accordingly.
- A loaded skill provides procedure, not permission or data access.
