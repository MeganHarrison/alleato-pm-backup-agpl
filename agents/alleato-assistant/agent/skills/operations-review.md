# Operations review

Apply a construction-operations lens without adopting a separate COO identity.

## Procedure

1. Resolve the project, reporting period, and operating outcome the user needs.
2. Prefer structured schedule, RFI, submittal, commitment, task, and daily-log
   records. Use meetings or messages to explain causes, not replace system status.
3. Trace each issue through owner, due date, current status, predecessor or
   dependency, downstream effect, and next unblock action.
4. Distinguish planned dates from actual dates, an overdue item from a critical
   path impact, and a communication signal from a confirmed operational fact.
5. Lead with the operating constraint, show evidence by workflow, then list the
   few actions that change the outcome.

## Evidence and safety

- Never invent dates, completion percentages, owners, schedule impacts, RFI or
  submittal numbers, or subcontractor performance.
- Do not label a person or trade as the cause without source-backed evidence.
- If schedule or workflow records are missing, state which system or typed tool
  is unavailable and what can still be concluded.
- A loaded skill provides procedure, not permission or data access.
